# AuditAI Case04 — Change Management

AI 도움을 받아 구현한 변경관리 검사 시연입니다. 사용자 실습·독립 수행 숙련은 별도로 진행 중입니다.

## 실행
기존 서버를 Ctrl+C로 종료하고 이 폴더에서 `py -m pip install -r requirements.txt`, `py app.py` 실행 후 브라우저에서 http://127.0.0.1:5000/case04 를 엽니다.

sample_data/Case04_Change_Management_Practice.xlsx를 업로드합니다. 기준일 2026-09-30 18:00, 긴급 승인 기한 48시간입니다.

## 검증된 예제 결과
전체 배포100 / 성공한 운영 배포98 / 검토 대상 배포11 / 규칙별 후보12.
D022의 24시간 후 긴급 승인은 기한 내입니다. D026의49시간 후 승인은 지연입니다. D046은 요청과 테스트가 모두 미연결이라2개 후보가 발생합니다.

## 정책 및 한계
합성 회사 정책: 일반 승인≤배포, 긴급 승인≤배포+48시간(경계 포함), 테스트Passed 및 완료≤배포, 개발자와 승인자·배포자 분리. 각 후보에 이유와 요청 증빙을 연결합니다. 고객의 실제 정책과 버전별 증빙을 적용하기 전에는 최종 통제 미비로 판단하지 않습니다.

입력 ID 중복·빈값과 잘못된 날짜·상태는 차단합니다. 테스트 입력은 변경별 최종 결과 한 건을 요구합니다. 여러 테스트 이력의 버전별 선택은 지원하지 않습니다. 결과·검토 기록의 영구 저장 및 공통 작업조서 기능은 아직 미구현입니다. 로컬 실행 패키지이며 공개 웹 배포 완료본은 아닙니다.

## 지원 포지셔닝
IT 감사·내부통제: 승인·테스트·직무분리 규칙을 코드로 실행하고 근거가 있는 검토 후보 제공.
프로세스 개선: 수작업의 자료 연결·검사·결과 출력을 일관된 흐름으로 자동화. 시간 절감 수치는 아직 측정하지 않음.
ISP·AX: 구조와 확장 방향을 설명하는 개인 프로젝트이며 실제 컨설팅 경험·AI Agent 운영 경험을 주장하지 않음.
