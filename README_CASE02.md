# AuditAI 2.0 · Case 01 + Case 02

합성 자료로 학습한 감사 검사를 웹에 연결한 개발 버전입니다. 실제 고객 감사나 상용 운영 이력을 주장하지 않습니다.

## Windows 실행
이 패키지는 기존 폴더와 별개로 압축을 풀어 사용합니다. 기존 Case01 기능을 포함합니다.
1. CMD에서 압축을 푼 AuditAI 폴더로 이동합니다.
2. `py -m pip install -r requirements.txt`
3. `py app.py`
4. 브라우저에서 http://127.0.0.1:5000/case02 접속합니다.
5. sample_data/Case02_Privileged_Access_JML.xlsx를 선택하고 검사 실행합니다.
6. 파일을 다시 선택하고 Excel 다운로드 버튼을 누르면 전체 결과가 저장됩니다.
기존 앱이 5000 포트에서 실행 중이면 그 CMD에서 Ctrl+C로 종료하고 새 앱을 실행합니다.

## 함수 및 연결
`privileged_check.py`: inspect_privileged_jml(hr, erp, roles, requests, jml, snapshot)
`app.py`: /case02 GET/POST, 업로드 및 Excel 다운로드
`templates/case02.html`: 요약 및 결과 표
`run_case02.py`: 웹 없이 함수 실행. `py run_case02.py sample_data/Case02_Privileged_Access_JML.xlsx`

ERP 권한 배정이 모집단입니다. 사번 → 역할 ID → 신청 ID → 사번 순으로 LEFT JOIN하고 연결 대상의 키 중복을 거부합니다. JML은 직원당 한 건이며 다중 이력은 사전 정리가 필요합니다. 시트 이름과 열 이름을 표준화해야 합니다. 열 순서는 자유이며 Excel 실습에서 추가한 열은 무시합니다.

## 연습 자료 예상 결과
ERP117건, 관리자 권한16건. 부서 및 직무: 일치13/불일치2/소유자확인1. 승인 시점: 충족13/사후1/확인2. 승인자: 일치13/불일치1/확인2. 만료: 만료일없음14/잔존1/승인기록확인1. 퇴사 권한2, 입사 전 부여2, 이동 후 잔존2. 중복 계정/역할 배정(U011) 등은 자료 확인 시트에 표시합니다. 서로 다른 검사 건수를 합산하여 고유 위반 수로 해석하지 않습니다.

## 학습 코드와 앱 함수의 차이
학습 코드는 단계별 조건 이해를 위해 작성했습니다. 앱 함수에는 필수 열·키·상태값·날짜 검증, 승인-권한 배정 ID 비교, 기준일과 변경일 다음 날 회수 기한을 추가했습니다. 회수일 누락은 증거 확인 대상으로 표시하고 계정 비활성화는 별도 증빙을 요구합니다. 부서/직무 일치는 이 합성 자료의 명시적 기준입니다. 사전 계정 준비는 입사 전 사용 가능 여부를 추가 검토합니다.

## 기여
박두이: AI 설명과 코드 예시를 참고한 Excel 검사, Python 단계별 작성·실행, 결과 대조.
AI: 학습 안내, 함수 정리·검증 보강, Flask 및 화면 연결, 테스트·포트폴리오 문서 작성.
미완료: 실제 고객 증빙 검토, 최종 결론·검토 이력 저장, 공개 배포, 사용자 인증, 회사별 열/정책 설정, 상용화 검증. 기존1.0 거래/PDF 기능은 전역 last_result를 사용하므로 다중 사용자 상용 서비스에 그대로 사용하지 않습니다. Case01/02는 요청별로 결과를 계산합니다.

## 검증
`py test_case02.py`로 합성 데이터 건수, 날짜 경계, 입력 오류, 업로드·다운로드를 확인할 수 있습니다. 테스트는 공개 배포나 고객 환경 검증을 대체하지 않습니다.
