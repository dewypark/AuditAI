# AuditAI 2.0 · 감사 분석과 증빙 검토를 연결하는 MVP

## 문제와 결과

HR·ERP·재무 자료를 수작업으로 연결해 이상 항목을 추출하면 검사 기준과 근거, 후속 검토 기록이 분산됩니다. AuditAI 2.0은 8개 검사 절차를 통합하고 원본·설정·후보·증빙 참조·검토 이력·작업조서를 같은 실행 단위로 연결합니다.

## 대상 업무

퇴사자 접근 회수, 관리자 권한/JML, SoD, 변경 승인/테스트, 인터페이스 대사, 전표 위험, 중복 지급/공급업체 위험, 규칙 점수 및 IsolationForest 기반 이상치 분석. 모든 결과는 검토 후보이며 감사인의 판단을 대체하지 않습니다.

## 구조

Flask 화면 → 입력 규격/열 매핑 및 검증 → Pandas 검사 함수 → 실행/후보 SQLite 저장 → 증빙 참조와 사람의 검토 → RCM·작업조서·XLSX 출력. Python/Flask/Pandas/scikit-learn/SQLite/openpyxl. 독립 SQL 검사 예제와 ERP 연동은 현재 범위 밖입니다.

## 시연 순서 · 3분

1. 대시보드에서 Case 04 합성 예제 실행. 일반 변경과 긴급 변경의 승인 기준이 다름을 설명.
2. D026의 49시간 지연, D046의 요청/테스트 미연결 근거를 확인. 후보 12건은 배포 11건임을 설명.
3. 증빙 요청과 티켓/로그 참조를 기록하고 검토 상태 변경. 이력 확인. 실무에서는 실제 원본 증빙을 확인하며, 시연의 참조 입력을 실제 증빙 검토로 주장하지 않음.
4. Case 05의 양방향 미연결·금액 차이를 실행. Case 08은 모델 후보가 부정 확정이 아님을 설명.
5. 작업조서와 XLSX를 다운로드. 결론은 사람이 쓰고 미완료 후보가 있으면 저장되지 않음을 보여줌.

## BPR·ISP·AX와 연결

| 관점 | 프로젝트에서 보여주는 것 | 증명하지 않는 것 |
|---|---|---|
| BPR | 수작업 자료 연결→검사→결과 정리→후속 검토를 실행 단위로 통합 | 실제 고객의 프로세스 인터뷰·개선 효과 측정 |
| ISP | 입력/검사/저장/검토/출력의 구조와 영구 디스크·ERP 연계 확장 계획 | 고객 전사 정보화 전략·투자계획 수립 |
| AX | AI 보조 개발, 모델과 규칙의 분석, 사람 검토·이력 | 자율 감사 Agent·고객 AX 전환 수행 |

## 검증과 한계

합성 자료와 명시적 오류 사례로 대사·전표·지급 규칙의 기대 결과를 검사. 날짜/숫자/ID 오류, 경계, 시연 실행·내보내기·검토 저장·재시작을 확인합니다. 예제 결과는 README에 기재합니다. 모델 부정 탐지 정확도와 업무 시간 절감은 측정하지 않았습니다. 합성 데이터 검증은 고객 자료 대응과 실제 통제 효과성을 보장하지 않습니다.

상용화 확장: 고객 모집단/정책별 설정, 다중 이력 처리, 로그인·권한·데이터 격리·보존·암호화, 증빙 업로드 및 외부 시스템 참조, 파일/ERP 연계, 운영 관측 및 사용성/효과 측정.
