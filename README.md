# AuditAI 2.0 — Digital Assurance MVP

합성 HR·ERP·재무 자료의 검사를 실행하고, 사람의 증빙 검토와 작업조서를 연결하는 **단일 사용자 시연 MVP**입니다. 8개 Case가 구현되어 있으며 공개 배포와 사용자 시연 검증은 별도입니다. 고객 감사 의견 또는 부정 판정을 자동 생성하지 않습니다.

## Windows 실행 — 이번 통합본

1. ZIP을 새 폴더에 압축 해제합니다. 기존 서버는 Ctrl+C로 종료합니다.
2. `app.py`와 `requirements.txt`가 있는 `AuditAI` 폴더에서 터미널을 엽니다.
3. 아래 순서로 실행합니다.

```bat
py -m pip install -r requirements.txt
py app.py
```

4. 브라우저 주소창에서 http://127.0.0.1:5000 을 엽니다. 터미널에 URL을 명령으로 입력하지 않습니다.
5. Case를 열고 **합성 예제 실행**을 누릅니다. 파일을 준비할 필요 없이 실행합니다.
6. 근거 확인 → 증빙 요청/수령/검토 기록 → 작업조서 및 결과 XLSX 다운로드로 시연합니다.

`app.py`는 새 통합 앱입니다. `legacy_app.py`와 `README_CASE01~04.md`는 이전 개별 기능의 코드/안내를 보존한 것으로, 현재 실행 안내는 이 README가 우선합니다.

## 구현

| Case | 검사 내용 |
|---|---|
| 01 | 기준일 이전 퇴사자, 회수 기한·활성 상태·HR 미연결 |
| 02 | 관리자 권한의 직무 필요성·승인·만료, Joiner/Mover/Leaver |
| 03 | 계정별 역할을 권한으로 확장, 충돌 조합과 보완통제 |
| 04 | 일반 사전 승인·긴급 48시간 승인, 배포 전 테스트, 독립성 |
| 05 | 양방향 거래 대사, 미연결·통화 불일치·금액 오차 |
| 06 | 통화별 전표 균형, 주말 수동·고액·자기 승인·기간 후보 |
| 07 | 동일 공급업체/송장/금액/통화 복수 지급, 미연결·비활성 업체, 계좌 공유 |
| 08 | 고액40/주말20/새벽20 점수 + 통화별 IsolationForest |

공통 기능: 입력 검증, 자료별 원본 열→표준 열 매핑 JSON 및 재사용, 실행 ID·규칙 버전·설정·원본 SHA256, 원본 다운로드, 후보 ID·이유·증빙 요청·원본 참조, 검토자/사유/증빙 참조/시각, 변경 이력, SQLite 저장, RCM/작업조서/결과 XLSX.

증빙은 **참조 식별자와 검토 기록**으로 관리합니다. 문서 업로드·진위 확인·실제 티켓 시스템 연결은 구현하지 않았습니다. 변경 이력은 수정 이벤트를 축적하지만 외부 불변 감사 로그는 아닙니다.

미완료 후보가 있으면 결론 저장을 차단합니다. 모든 후보를 검토한 후 사람이 범위·확인사항·한계를 적습니다. 기존 후보를 다시 수정하면 결론이 해제되고 이전 결론은 이력에 남습니다. `검토 완료·지적 후보`는 확정 deficiency 판정이 아닙니다.

## 입력 및 규칙 한계

- 각 Case 화면에 필수 자료명·열이 표시됩니다. XLSX는 표준 시트 이름, JSON은 자료명→행 목록을 사용합니다. 열 이름은 화면에서 매핑할 수 있습니다. 시트 이름 자동 매핑/ERP 커넥터는 없습니다.
- 날짜는 시간대 없는 KST 입력. 실행/검토 기록 시각은 UTC입니다.
- ID 연결과 숫자·날짜 검증으로 자료 자체의 외부 완전성·진위를 입증하지 않습니다. 추출 모집단에 대한 시스템 대사/관리자 확인은 추가 절차입니다.
- Case 01: 기준일 상태를 반영한 ERP 명부가 필요하며 로그 없이 실제 접근이나 적시 회수를 확정하지 않습니다. 다음 날 00:00 **이전** 회수 정책입니다.
- Case 02: 직원당 JML 이벤트 한 건. Case 03: 계정/규칙당 보완통제 한 건. Case 04: 변경당 테스트 최종 기록 한 건을 요구합니다. 다중 이력·버전 선택은 확장 과제입니다.
- Case 05: 각 자료에 거래 ID 한 건. 중복 거래 ID는 차단합니다. 여러 라인 거래는 전처리 집계 후 입력합니다. 금액 차이 **> 허용 오차**가 후보입니다. 통화가 다르면 비교 후보로 분리하며 합산하지 않습니다.
- Case 06: 전표/통화별 차변 대변을 비교합니다. 일부 라인만 추출하면 균형 검사가 의미 없으므로 전표 전체 모집단이 필요합니다. entry_type은 Manual/System, 작성자/승인자는 필수입니다. `-` 등 대체 식별자는 미승인 검사를 대신하지 못합니다.
- Case 07: Paid만 검사, Void 제외. invoice_no는 대소문자와 앞뒤 공백 정규화. 동일 키 복수 지급은 부분/정상 재지급일 수 있습니다. 업체 상태는 기준일 명부이므로 지급 당시 상태 이력은 추가 확인합니다.
- Case 08: 통화별 20건 이상에서 모델 실행, 로그 절대 금액·시간·요일 입력, random_state=42. 같은 모집단에서 학습/점수화하는 탐색 분석이며 독립 평가·성능·부정 확률을 주장하지 않습니다. contamination은 점수 임계값 목표로, 동점 때문에 실제 후보 비율이 같지 않을 수 있습니다. 금액 기준은 각 통화에 같은 숫자로 적용하므로 고객의 통화별 정책으로 조정이 필요합니다.

## 저장·배포

기본 SQLite·세션 키는 `instance/`에 생성됩니다. 프로세스를 재시작해도 결과와 검토 이력이 남습니다. 브라우저 세션 쿠키로 실행을 구분하며 다른 브라우저에는 보이지 않습니다. 로그인/계정 복구 기능이 없어 쿠키를 지우면 기존 실행에 다시 접근할 수 없습니다. 필요한 결과를 다운로드하세요.

배포 시작 명령: `gunicorn app:app`. Python 3.12 권장. 환경 변수 `AUDITAI_DATA_DIR`를 영구 디스크 경로로 설정하고, 안정적인 `SECRET_KEY`를 지정하세요. 영구 디스크 없이 호스팅을 재시작하면 기록이 사라집니다. HTTPS 배포에서는 `AUDITAI_SECURE_COOKIE=1`을 지정하세요.

이 패키지에는 공개 URL이 포함되지 않습니다. 공개 시연에는 합성 자료만 사용하세요. 로그인·역할 권한·암호화/보존 정책·백업·다중 고객 분리·업로드 크기 외 자원 제한·운영 모니터링을 검증하기 전 고객 기밀자료를 받는 상용 서비스로 제공하지 않습니다.
