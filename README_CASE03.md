# Case 03 직무분리 (SoD)

이 패키지는 Case01/02/03 및 기존 거래 기능을 포함합니다. 기존 앱을 종료하고 새 폴더에서 실행합니다.

## 실행
```bat
py -m pip install -r requirements.txt
py app.py
```
브라우저 http://127.0.0.1:5000/case03 에서 sample_data/Case03_SoD_Practice.xlsx를 업로드합니다. 다운로드하려면 다시 파일을 선택합니다. 공개 배포는 아직 수행하지 않았습니다.

## 학습 상태
Case03은 AI가 작성한 구현입니다. 박두이의 Excel/Python 독립 실습·코드 설명·증빙 검토·최종 감사 결론은 이후 진행할 예정입니다. Case01/02의 직접 실습과 구분합니다.

## 규칙과 모집단
기준일2026-09-30 18:00 KST. Active 계정의 부여일<=기준일이며 회수일 공란 또는 기준일보다 늦은 권한을 검사합니다. 회수일=기준일은 회수된 것으로 봅니다.
- SOD01 거래처 등록/변경 + 지급 실행
- SOD02 청구서 작성 + 청구서 승인
- SOD03 전표 입력 + 전표 승인
역할-권한 매핑으로 실제 권한을 펼쳐 계정별 집합을 만들고 규칙의 두 권한 보유 여부를 검사합니다. 한 역할 안의 충돌도 식별합니다. 계정·규칙 조합당 한 후보로 집계하고 역할·배정ID를 추적할 수 있습니다. 여러 역할 때문에 같은 권한이 반복되어도 후보 수는 중복 증가하지 않습니다.

## 합성 자료와 예상 결과
100계정,109권한배정,12역할-권한매핑,3충돌규칙,3완화통제기록.
충돌8개 계정·규칙 조합/고유계정5개:
U002 SOD01, U006 SOD02, U010 SOD03, U020 SOD01/SOD02, U050 SOD01/SOD02/SOD03.
U030 지급 권한은 회수되어 제외, U040은 Disabled로 제외.
U099 R_UNKNOWN은 권한 매핑이 없어 자료 확인에 남습니다. 매핑 누락이 있으면 미탐지 가능성이 있으므로 전체 검사 완료로 결론 내리지 않습니다.
U002의 완화 통제는 유효 승인 기록이 있으나 운영 증빙 검토가 남습니다. U006은 만료, U010은 승인 대기입니다. 후보를 자동 삭제하지 않습니다.

## 입력 계약
시트/열 이름은 sample_data를 따릅니다. 계정ID/배정ID/규칙ID/완화통제ID는 유일해야 합니다. 역할-권한 매핑은 다대다 관계이며 같은 쌍의 중복은 금지합니다. 완화 통제는 계정·규칙당1건입니다. 계정 상태Active/Disabled, 승인상태Approved/Pending/Rejected. 날짜는 시간대 표기 없는 KST입니다. 원본 자료는 모두 합성입니다.
